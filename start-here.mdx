Orca 2.0 runs AI agents for you in the cloud. You describe an agent once, as a model, its instructions and its tools, and Orca runs every conversation with it to the end: it calls the model, runs the tools, works on a private machine when the job needs one, keeps the history, and streams it all back as it happens. Your code talks to Orca through the OpenAI Agents API with the official `openai` package, so there is no SDK of ours to learn.

This page gets you hands on with a sample agent called Scout, a research assistant that searches the web and cites its sources. You'll copy it into your account, give it real questions, give it a machine of its own, then drive it from your coding agent and from a few lines of code.

The commands below run in bash, zsh, and fish, on macOS and Linux. Where the shells differ, a block has a tab for each. Run them in one terminal, since later steps use variables that earlier ones set.

## 1. Install the CLI and sign in

```bash
curl -fsSL https://orcapods.ai/install.sh | sh
orca --version
```

The script installs a single `orca` binary to `~/.local/bin`. If your shell then says `orca: command not found`, add that folder to your `PATH` as the script suggests, and open a new terminal. On Windows, download the binary from the [releases page](https://github.com/okikorg/orca-cli/releases). An older CLI updates itself with `orca update`.

```bash
orca login
```

It prints a one-time code and a link to the Orca dashboard. Open the link, sign in, check that the code matches, and choose **Approve**. The CLI then prints "Logged in to Orca as" your role and organization. It works the same over SSH and inside a coding agent, which relays the code and the link to you.

Check your credit:

```bash
orca billing wallet
```

`balance` is your Orca credit. The amount new accounts start with is on the [pricing page](https://orcapods.ai/pricing).

## 2. Copy Scout and see how it's built

Scout is published as a [kit](/kits): a link that anyone can copy an agent from. Copy it into your account:

```bash
orca kits copy https://app.orcapods.ai/kits/kit-tdCEUXGA3NbuIWJJ6 --yes
```

The CLI prints the agent it created, `scout`, with its ID. Now look at what you copied:

```bash
orca agents get scout
```

This is all of Scout, as you would create it from code with the `openai` package:

<CodeGroup>
```python Python
agents.create(
    name="scout",
    model="orca/openrouter/openai/gpt-5.6-luna",
    instructions=(
        "You are Scout, a research assistant. Answer in a few short paragraphs or a short list.\n"
        "Search the web when the answer depends on facts that change, such as releases, versions, "
        "prices or news, and cite each source with its link.\n"
        "If the sources disagree, or you cannot find an answer, say so instead of guessing."
    ),
    tools=[{"type": "web_search"}],
)
```
```typescript TypeScript
await agents.create({
  name: 'scout',
  model: 'orca/openrouter/openai/gpt-5.6-luna',
  instructions:
    'You are Scout, a research assistant. Answer in a few short paragraphs or a short list.\n' +
    'Search the web when the answer depends on facts that change, such as releases, versions, ' +
    'prices or news, and cite each source with its link.\n' +
    'If the sources disagree, or you cannot find an answer, say so instead of guessing.',
  tools: [{ type: 'web_search' }],
});
```
</CodeGroup>

A model, its instructions, and the tools it may use. There is no loop to write, no search API to call, and no history to store: Orca runs each conversation to the end, calls the search when the model asks for it, and keeps every message. The model name also says who pays. `orca/openrouter/<id>` runs on your Orca credit; `<provider>/<id>`, such as `anthropic/claude-sonnet-4-5`, runs on your own key for that provider. See [models and provider keys](/providers).

## 3. Put Scout to work

Ask it something it has to look up:

```bash
orca chat scout "What's new in the latest Python release? Cite your sources."
```

The reply streams into your terminal as the model writes it, after the searches it ran. The line `session session_...` names the session (the conversation) it started. Run `orca chat scout` with no message for a back-and-forth conversation; Ctrl-C leaves it.

Each `orca chat` without `--session` starts a new conversation. To keep one going, create a session and pass its ID:

<CodeGroup>
```bash bash / zsh
SESSION=$(orca sessions create --agent scout)
orca chat scout --session "$SESSION" "Which three Python web frameworks are most used today?"
orca chat scout --session "$SESSION" "Compare the first two in a short table."
orca sessions items "$SESSION"
```
```fish fish
set SESSION (orca sessions create --agent scout)
orca chat scout --session "$SESSION" "Which three Python web frameworks are most used today?"
orca chat scout --session "$SESSION" "Compare the first two in a short table."
orca sessions items "$SESSION"
```
</CodeGroup>

Scout knows what "the first two" means, because the session keeps the conversation. `orca sessions items` prints it all, and Orca keeps it on the server, so you can come back to it tomorrow.

## 4. Give Scout a machine of its own

A sandbox is a private machine for one session, where the agent can run commands and write files. Files it saves under `/workspace/outputs` are kept as artifacts when its turn completes:

<CodeGroup>
```bash bash / zsh
BOX=$(orca sessions create --agent scout --sandbox)
orca chat scout --session "$BOX" "Use Python to write the first 20 prime numbers to /workspace/outputs/primes.txt, one per line, then show me the file's contents."
orca sessions artifacts "$BOX"
orca sessions artifacts download "$BOX" /workspace/outputs/primes.txt
cat primes.txt
orca sessions delete "$BOX" --yes
```
```fish fish
set BOX (orca sessions create --agent scout --sandbox)
orca chat scout --session "$BOX" "Use Python to write the first 20 prime numbers to /workspace/outputs/primes.txt, one per line, then show me the file's contents."
orca sessions artifacts "$BOX"
orca sessions artifacts download "$BOX" /workspace/outputs/primes.txt
cat primes.txt
orca sessions delete "$BOX" --yes
```
</CodeGroup>

Scout writes and runs the code on its machine, and the reply shows the file. `orca sessions artifacts download` saves it here as `primes.txt` (`--all` saves every file the last turn left in `/workspace/outputs`). To give Scout a file of yours, add `--file data.csv` to `orca chat` or `orca sessions create`: it lands at `/workspace/data.csv`. Your code can do the same [with the API](/guides/files-and-artifacts#get-results-back-as-artifacts). Deleting the session stops its sandbox and deletes its artifacts.

Start a new session of your coding agent so it loads the server. Then ask it things like:

- "Ask Scout to research the trade-offs between SQLite and Postgres for a small app, and summarize its answer."

Your coding agent acts as you with these tools: it can create, delete, and spend. See [use Orca from coding agents](/cli/mcp) for every tool.

## 6. Run Scout from your own code

Everything so far went through the CLI, which calls the same API your application would. Your code uses the official `openai` package with an Orca API key. Make one with the CLI and keep it in your shell as `ORCA_API_KEY`:

<CodeGroup>
```bash bash / zsh
export ORCA_API_KEY=$(orca keys create start-here </dev/null)
```
```fish fish
set -x ORCA_API_KEY (orca keys create start-here </dev/null)
```
</CodeGroup>

The key is shown only once, so this stores it without printing it. You can also create one in the dashboard under **Settings**, **API keys**.

Install the client. You need Python 3.10 or later, or Node 22.18+ or 24+, which runs `.ts` files directly:

<CodeGroup>
```bash Python
python3 -m venv .venv
.venv/bin/pip install openai==3.13.0
```
```bash TypeScript
npm init -y && npm pkg set type=module
npm install openai@7.15.0
```
</CodeGroup>

This program finds Scout, opens a session, and streams one answer:

<CodeGroup>
```python scout.py
import os

from openai import OpenAI

client = OpenAI(api_key=os.environ["ORCA_API_KEY"], base_url="https://api.orcapods.ai/v1")
agents = client.beta.agents

scout = next(agent for agent in agents.list() if agent.name == "scout")
session = agents.sessions.create(agent_id=scout.id, environment={"type": "none"})
try:
    with agents.sessions.stream(session.id, input="What is the latest Node.js LTS release? Cite your source.") as stream:
        for event in stream:
            if event.type == "agent.session.turn.output_text.delta":
                print(event.delta, end="", flush=True)
            elif event.type in ("agent.session.turn.failed", "agent.session.turn.cancelled"):
                print("\nThe turn ended:", event.type)
    print()
finally:
    agents.sessions.delete(session.id)
```
```typescript scout.ts
import OpenAI from 'openai';

const client = new OpenAI({ apiKey: process.env.ORCA_API_KEY, baseURL: 'https://api.orcapods.ai/v1' });
const agents = client.beta.agents;

let scout;
for await (const agent of agents.list()) if (agent.name === 'scout') { scout = agent; break; }
if (!scout) throw new Error('No agent called scout. Copy it first (step 2).');

const session = await agents.sessions.create({ agent_id: scout.id, environment: { type: 'none' } });
try {
  for await (const event of agents.sessions.stream(session.id, { input: 'What is the latest Node.js LTS release? Cite your source.' })) {
    if (event.type === 'agent.session.turn.output_text.delta') process.stdout.write(event.delta);
    else if (event.type === 'agent.session.turn.failed' || event.type === 'agent.session.turn.cancelled') {
      console.log('\nThe turn ended:', event.type);
    }
  }
  console.log();
} finally {
  await agents.sessions.delete(session.id);
}
```
</CodeGroup>

<CodeGroup>
```bash Python
.venv/bin/python scout.py
```
```bash TypeScript
node --experimental-strip-types scout.ts
```
</CodeGroup>

Scout lives on Orca, so your code only opens a session and reads the answer. The [quickstart](/quickstart) explains each call, including how to create agents from code.

## 7. See what it cost, and clean up

Every call is recorded with what it cost, down to the session:

```bash
orca sessions get "$SESSION"   # one session's cost, tokens, and machine time
orca usage --days 1            # today's usage, by the hour
orca billing wallet            # your balance and plan
```

- **Model tokens and web searches** on an Orca credit model are paid from your credit. On your own provider key, that provider bills you.
- **Sessions without a sandbox use no machine time.** On this page, only step 4 used any.
- **Sandboxes use [machine time](/plans#machine-time)** from your plan, and need your plan's [minimum balance](/plans#paid-work-needs-a-minimum-balance) of Orca credit in your wallet, even for included time. Delete a sandbox session when you are done with it.

The numbers for each plan, the signup credit, and the minimum balance are on the [pricing page](https://orcapods.ai/pricing). See [usage and wallet](/wallet#read-the-wallet-and-your-usage) for the rest.

Keep Scout if you like it, and make it yours: change its instructions or model on its page in the [dashboard](https://app.orcapods.ai/agents). To remove everything this page made instead, delete Scout's sessions, then Scout, then the key. Deleting an agent does not delete its sessions.

<CodeGroup>
```bash bash / zsh
for id in $(orca sessions list --agent scout --all | cut -f1); do orca sessions delete "$id" --yes; done
orca agents delete scout --yes
orca keys list
```
```fish fish
for id in (orca sessions list --agent scout --all | cut -f1); orca sessions delete "$id" --yes; end
orca agents delete scout --yes
orca keys list
```
</CodeGroup>

Then revoke the key named `start-here` with `orca keys revoke <its id> --yes`, and close the terminal: its `ORCA_API_KEY` still holds the revoked key.
