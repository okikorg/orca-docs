Orcacode is a coding agent that runs in your terminal. You talk to it in plain words. It reads your files, runs commands and makes edits, and it asks before it changes anything. It is open source under the Apache License 2.0, on [GitHub](https://github.com/okikorg/orca-harness).

This page takes about five minutes. Every command on this page runs as written on orcacode 0.9.0 on macOS.

## 1. Install

On macOS or Linux:

```bash
$ curl -fsSL https://orcapods.ai/orcacode.sh | sh
```

On Windows, in PowerShell:

```bash
> irm https://orcapods.ai/orcacode.ps1 | iex
```

Check that it worked:

```bash
$ orcacode --version
orcacode 0.9.0
```

On macOS and Linux the installer puts one file in `~/.local/bin`. If that folder is not on your `PATH`, the installer tells you how to add it. [Install & run](/orcacode/install) has other install options.

## 2. Start it

Go to a project you want to work on and start Orcacode:

```bash
$ cd your-project
$ orcacode
```

It opens full screen in your terminal. This is a first launch with nothing set up:

```text
            ▀▄ ORCACODE  v0.9.0
            A small, fast agent runtime for your terminal

            model      gpt-4o-mini
            workspace  /private/tmp/claude-501/-Users-atiya-Documen…  ⑂ main
            recent     0s ago    gpt-4o-mini  3b151a4f

            › Describe a task to begin
            /help      commands
            /models    switch model
            /mode      plan, orchestrate, auto, yolo
            /sessions  resume a session

│ ask anything · @ add files · /help commands
 openai:gpt-4o-mini · ctx ~0 · enter send  @ paths  ctrl+o expand  ctrl+t split   ⑂ main
```

The middle shows the model, the folder it works in and your recent sessions. You type on the line that starts with `│`. The line under it shows which provider and model you are using.

With no key and no settings, Orcacode asks a local server at `http://localhost:11434/v1` for `gpt-4o-mini`. Unless you run one there with that model, a question just retries. Press `Esc` to stop it:

```text
┃ What does this project do?
• model request failed · parent · retrying
  ■ working · 3m 18s · ↑6 ↓0 · esc to interrupt
```

So connect a model first.

## 3. Connect a model

Type `/provider` and press `Enter`. Use the arrow keys to pick one, then `Enter` again.

```text
  Select provider · ↑↓ move  →/enter use  esc close
    openai-codex  https://chatgpt.com/backend-api/cod…  subscription OAuth · signed in …
    local         http://localhost:11434/v1             no key needed
```

The list also has `openrouter`, `vercel`, `cheaperinference`, `openai` and `anthropic`. Pick the one that matches what you have:

- **A ChatGPT subscription:** pick `openai-codex`. If you have signed in to the Codex CLI on this computer, Orcacode uses that login and switches right away. If not, it shows a code to enter at `https://auth.openai.com/codex/device`. No API key needed.
- **An API key:** set the key before you start Orcacode. Use `OPENAI_API_KEY` for `openai`, `ANTHROPIC_API_KEY` for `anthropic`, `OPENROUTER_API_KEY` for `openrouter` or `AI_GATEWAY_API_KEY` for `vercel`. If you pick one without its key set, Orcacode asks for it and saves it:

  ```text
    openai API key (saved for future sessions) · enter confirm  esc close
    key:
  ```

- **Ollama, no key:** start Ollama and pull a model, then pick `local`. Orcacode lists the models your Ollama server has.

After you pick, Orcacode confirms the provider and model:

```text wrap
provider: openai-codex · model: gpt-6.1-sol
```

Now type `/models` to choose the model. `/models` is what saves your choice, so the next launch starts on the same model.

```text
  Models · type to filter · →/enter switch  esc close                              1/9
  Missing models? Update Orcacode or check account access.
  › gpt-6.1-sol        500k ctx
    gpt-6-astra        272k ctx
    gpt-6-sol          272k ctx
    gpt-6-luna         272k ctx
```

Some models then ask for a reasoning effort. `low` is quickest.

```text wrap
model: gpt-6.1-sol · effort low
```

## 4. Ask it about your repo

Type a question and press `Enter`:

```text wrap
┃ What does this project do, and where is the retry logic?
```

To look around, it may want to run shell commands. Each one asks first. Press `y` to allow it.

```text
  ╭─ ! Approval required · shell ──────────────────────────────────────────────────────╮
  │ shell $ pwd; ls -la; find . -maxdepth 2 -type f \( -name 'README*' -o -name        │
  │ 'package.json' -o -name…                                                           │
  │                                                                                    │
  │   Allow once                                                                     y │
  │   Always this session                                                            a │
  │   Always for workspace                                                           A │
  │   Deny                                                                           n │
  ╰─────────────────────────────────────────────── ↑↓ choose  enter confirm  esc deny ─╯
```

## 5. Let it change something

Ask for one small change:

```text wrap
┃ Fix that off-by-one: max_attempts is the total number of attempts allowed.
```

Before it edits a file, it shows the change and asks:

```text
  ■ Work · ■ 1 · □ 1
    ├─ ■ Shell · $ cat src/retry.rs; command -v … · exit 0 · pub fn should_retry… · 30ms
    └─ □ Edit · src/retry.rs · 3.3s
       - pub fn should_retry(attempts_made: u32, max_attempts: u32) -> bool {
       -     attempts_made <= max_attempts
       - }
       + pub fn should_retry(attempts_made: u32, max_attempts: u32) -> bool {
       +     attempts_made < max_attempts
       + }
         … 20 more changed lines
  ╭─ ! Approval required · edit_file ──────────────────────────────────────────────────╮
  │ edit_file src/retry.rs                                                             │
  │                                                                                    │
  │   Allow once                                                                     y │
  │   Always this session                                                            a │
  │   Always for workspace                                                           A │
  │   Deny                                                                           n │
  ╰─────────────────────────────────────────────── ↑↓ choose  enter confirm  esc deny ─╯
```

- `y`: allow this one call.
- `a`: allow this tool for the rest of the session.
- `A`: always allow this tool in this folder. You can take it back in `/settings`.
- `n`: say no. The call does not run.

After `y`:

```text
  ■ Work · 3 tools
    ├─ ■ Shell · $ cat src/retry.rs; command -v … · exit 0 · pub fn should_retry… · 30ms
    ├─ ■ Edit · src/retry.rs · approved · 1 replacement · 7.6s
    │  - pub fn should_retry(attempts_made: u32, max_attempts: u32) -> bool {
    │  -     attempts_made <= max_attempts
    │  - }
    │  + pub fn should_retry(attempts_made: u32, max_attempts: u32) -> bool {
    │  +     attempts_made < max_attempts
    │  + }
    │    … 20 more changed lines
    └─ ■ Shell · $ test_bin=$(mktemp /tmp/northstar-r… · exit 0 · running 2 tests · 1.0s
  Fixed src/retry.rs: should_retry now uses attempts_made < max_attempts, so no retry is
  allowed once the total attempt limit is reached.
  Added boundary tests covering below, at, and above the limit, plus zero- and
  single-attempt limits.
  Verification: both tests passed; git diff --check passed.
  done · 25.6s · 3 tools · ↑19 ↓450
```

The change is a normal edit in your repo, so check it with git as usual:

```bash
$ git diff --stat
 src/retry.rs | 22 +++++++++++++++++++++-
 1 file changed, 21 insertions(+), 1 deletion(-)
```

Later, you can change how much it asks. `Shift+Tab` cycles through the modes, or pick one with `/mode`. In the command list, `/models` comes first, so press `↓` to reach `/mode`.

```text
  Select mode · ↑↓ move  →/enter use  esc close
  › normal      gated tools ask for approval                    current
    plan        read-only: investigate and propose, change no…
    orchestra…  delegate substantial work; basic edits allowed
    auto        safe tools run; unresolved actions get review…
    yolo        every gated tool runs without asking
```

`normal` asks before commands and edits. `plan` only reads and suggests. `auto` lets safe steps run and reviews the rest. `yolo` never asks, so use it only when you mean it.

## 6. Come back later

When you quit, Orcacode prints how to get back to that session:

```text
orcacode · session ended · tokens in 39870 out 1073
Resume this session with:
  orcacode resume 3f18a9f2-3390-4066-945d-457e8bdb18dd
```

To pick up the latest session in this folder, start with `--continue`. The conversation is still there:

```bash
$ orcacode --continue
```

## 7. Getting around

Type `/` to see every command. Keep typing to filter the list. `/help` shows the same list.

```text
  Commands · type to filter · →/enter run  tab complete  esc close                1/26
  › /help        general  show available slash commands
    /hotkeys     general  show all registered keyboard shortcuts
    /changelog   general  show latest release changes, or full history with `full`
    /clear       session  preserve this session, start fresh, and stop background work
```

The keys you will use most, from `/hotkeys`:

```text
  Enter                     send a prompt, or queue it while the agent is running  Composer
  Shift+Tab                 cycle normal, plan, orchestrate, auto, and yolo modes  Composer
  Up / Down                 browse prompt history, or move in the command palette  Navigation
  Ctrl+O                    expand the latest work or tool output  Actions
  Esc                       close the active UI, clear the prompt, or interrupt a run  Actions
  Ctrl+C                    interrupt, clear the prompt, or quit when idle  Actions
  Ctrl+D                    quit when the prompt is empty  Actions
```

To quit, press `Ctrl+D` on an empty prompt, or type `/quit`.
