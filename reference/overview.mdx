## Base URL

All paths in this reference are relative to the Orca base URL:

```text
https://api.orcapods.ai/v1
```

The official clients take this as `base_url` (Python) or `baseURL` (TypeScript). Agents, sessions, environments, and vaults are under `client.beta.agents`; files and skills are under `client.files` and `client.skills`.

Orca's own extensions live outside `/v1`; see [Orca extensions](#orca-extensions).

## Authentication

Send your Orca API key as a bearer token on every request. A missing or invalid key returns `401`.

```bash
curl -H "Authorization: Bearer $API_KEY" "$BASE_URL/agents?limit=10"
```

```python
from openai import OpenAI
client = OpenAI(api_key="YOUR_ORCA_KEY", base_url="https://api.orcapods.ai/v1")
```

The key determines your [organization](/organizations) and your role in it. You only see your organization's resources; anything else returns `404`. An action your role does not allow returns `403`. Keep keys out of source control.

Create keys in the dashboard under **Settings**, **API keys**, with `orca keys create`, or with `POST /api/keys`.

JSON requests use `Content-Type: application/json`. File and skill uploads use `multipart/form-data`.

## Pagination

Most list endpoints use cursor pagination:

| Parameter | Meaning |
| --- | --- |
| `limit` | Page size |
| `order` | `asc` or `desc` |
| `after` | The ID of the last item on the previous page |

The response contains `object: "list"`, `data`, `first_id`, `last_id`, and `has_more`. While `has_more` is true, request the next page with `after=<last_id>`. The Python and TypeScript clients do this for you when you iterate the result.

Some lists take extra filters: sessions accept `agent_id`, artifacts accept `environment_id`, and vaults and credentials accept `status`.

**Environment file listing is different.** Its response has `data`, `has_more`, and an opaque `next` token. Pass `next` as `page` to get the following page, not `after`.

## Compatibility

Orca implements the OpenAI Agents API. The [OpenAI Agent API quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart/) is useful background, but Orca is a separate implementation:

- **Supported routes** are exactly those listed in this reference. They were checked against the official clients at **Python `openai` 3.13.0** and **TypeScript `openai` 7.15.0**.
- **Other client versions** may add or rename methods that Orca does not support.
- **On hosted Orca**, `self_hosted` environments are coming soon, `network.access: "restricted"` is not available, and remote MCP servers are limited to an [allowed list](/guides/mcp#allowed-servers).
- **Event payloads**: Orca sends the event types listed in [events](/reference/events). Handle unknown event types gracefully.

## Rate limits

Each plan sets how many requests a minute an organization can make, and each key or signed-in person in it; the numbers are on the [pricing page](https://orcapods.ai/pricing). Past that, requests return HTTP 429 `rate_limit_exceeded`, "Rate limit reached. Retry after N seconds.", with a `Retry-After` header. Your plan also limits [turns a day, sessions at once, API keys and stored sessions](/plans#limits-per-plan).

Routes that need no key, such as the public plans and kits pages and `orca login`, allow 120 requests a minute from one IP address. An IPv6 address counts with the rest of its `/64`.

A few things are also limited by how many are open at once. Each refusal is retryable and carries a `Retry-After` header.

| What | At once | Past that |
| --- | --- | --- |
| [Event streams](/guides/streaming#how-many-streams) | 32 per key or signed-in person, 64 per organization | HTTP 429 `rate_limit_exceeded` |
| [File uploads](/guides/files-and-artifacts#size-limits) | 2 per organization | HTTP 429 `rate_limit_exceeded` |

### Session sandbox

`GET /api/sessions/{session_id}/sandbox` reads a session's sandbox, and `POST /api/sessions/{session_id}/sandbox/sleep` puts it to sleep now (see [put a sandbox to sleep now](/guides/environments#put-a-sandbox-to-sleep-now)). Both need the member role and return the same object:

```json
{
  "object": "session.sandbox",
  "session_id": "session_…",
  "environment_id": "env_…",
  "state": "asleep",
  "last_sleep": {
    "reason": "requested",
    "started_at": 1792483200,
    "finished_at": 1792483209,
    "outcome": "asleep",
    "message": null
  }
}
```

| Field | Meaning |
| --- | --- |
| `state` | `awake`, `going_to_sleep`, `asleep`, `waking`, or `none` when the session has no managed sandbox (no environment, a self-hosted one, or one that failed to start). |
| `environment_id` | The session's environment, `null` when `state` is `none`. On `/v1` its `status` reads `disconnected` while asleep and `pending` while waking. |
| `last_sleep` | The last time the sandbox went to sleep, or tried to, since it last woke; `null` if it has not. |
| `last_sleep.reason` | Why it went to sleep: `requested` (someone put it to sleep), `idle` (the idle time passed), `out_of_credit`, `hours_used_up` or `unpriced` (Orca stopped its machine time; see [when credit runs low](/wallet#when-credit-runs-low)), `suspended` (Orca suspended work for the organization: "Work for this organization is suspended. Ask on Discord: https://discord.gg/btTYzdzvqq"), or `network_on` (a Free sandbox that started without the network, now that its organization has credit, so that its next start has it; see [machine time on Free](/plans#machine-time-on-free)). More reasons may be added; show one you do not know as asleep. |
| `last_sleep.outcome` | `null` while going to sleep, then `asleep`, or why it stayed awake: `too_large` (its files are too large to save), `failed` or `interrupted` (a message or a file request reached it first, or the server restarted); or, on Free, `discarded`: a workspace Orca could not save when it stopped the sandbox was not kept, `state` reads `none`, and the next message starts a new, empty sandbox. |
| `last_sleep.message` | A message to show the user: for an outcome other than `asleep`, for a `suspended` or `network_on` sleep, and for a Free workspace saved near the size Free keeps. |

The POST takes an empty body or `{}`. It returns as soon as the sandbox starts going to sleep; poll the GET to see it finish.

| Case | Status | Body |
| --- | --- | --- |
| Awake, sleep started | 202 | The object, `state: "going_to_sleep"`, `last_sleep.outcome: null` |
| Already going to sleep | 202 | The object |
| Already asleep | 200 | The object |
| No managed sandbox | 200 | The object, `state: "none"` |
| A turn is running | 409 `conflict` | "A turn is running; put the sandbox to sleep once it ends." |
| Starting up or waking up | 409 `conflict` | "The sandbox is waking up; put it to sleep once it is awake." |
| Unknown session | 404 | |

```bash
export ORCA_ORIGIN="https://api.orcapods.ai"
curl --fail-with-body -X POST "$ORCA_ORIGIN/api/sessions/$SESSION_ID/sandbox/sleep" \
  -H "Authorization: Bearer $ORCA_API_KEY"
```

```json
{"object": "session.sandbox", "session_id": "session_…", "environment_id": "env_…", "state": "going_to_sleep",
 "last_sleep": {"reason": "requested", "started_at": 1792483200, "finished_at": null, "outcome": null, "message": null}}
```
