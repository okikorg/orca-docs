This is a route-oriented reference for this server's verified public surface. Start with the **[official OpenAI Agents API quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart/)** for upstream concepts; for a runnable server-specific introduction see [Quickstart](/quickstart), then [Streaming](/guides/streaming). Browse [Agents](/reference/agents), [Sessions](/reference/sessions), [Resources](/reference/resources), [Events](/reference/events), and [Errors](/reference/errors).

The paths in these pages are relative to a `/v1` base URL. The server works with the official OpenAI Python and TypeScript clients configured with that base URL. This reference covers the routes verified in the pinned endpoint inventory, not an OpenAPI specification or a promise of complete compatibility with future upstream releases. The schema inventories are SDK type snapshots, **not** a full wire specification. Provider/model availability and sandbox capabilities depend on the service configuration.

## Authentication and requests

Send `Authorization: Bearer <server API key>` on requests. An absent or invalid key returns `401`. Keys scope access to a tenant; use HTTPS for remote connections and keep keys out of source control. JSON requests use `Content-Type: application/json`; file and skill uploads use multipart. For example, with `BASE_URL=https://your-server.example/v1`:

```bash
curl -H "Authorization: Bearer $API_KEY" "$BASE_URL/agents?limit=10"
```

In Python, set `openai.OpenAI(api_key=..., base_url="https://your-server.example/v1")`; in TypeScript set `new OpenAI({ apiKey: ..., baseURL: "https://your-server.example/v1" })`. For this server, use a server API key rather than assuming an upstream OpenAI key grants access.

## Pagination

Most list endpoints use cursor pagination: `limit`, `order=asc|desc`, and `after` (the last item's ID from the preceding page). List responses contain `object: "list"`, `data`, `first_id`, `last_id`, and `has_more`. Request another page with `after=<last_id>` while `has_more` is true. Session lists additionally accept `agent_id`; artifact lists additionally accept `environment_id`; vault lists accept `status`. **Environment file listing differs**: its response contains `data`, `has_more`, and an opaque `next` token; pass `next` as `page` for the following request, not `after`. Consult [Resources](/reference/resources). Do not treat a list as a full result set without paging.

## Version scope

Routes and SDK names were checked against the pinned **OpenAI TypeScript 7.15.0** and **Python 3.13.0** client inventories. SDK calls use `beta.agents` for agents, sessions, environments, and vaults; files and skills use `files` and `skills`. The pinned inventories record paths, parameter types, response types and selected event discriminators; they do not establish that every upstream SDK type, model, event payload or future API feature is supported. See [Errors](/reference/errors) for HTTP failures and [Events](/reference/events) for streaming.
