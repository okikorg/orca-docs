Run `orca <command> --help` for every flag. Where a command takes `[agent]` or another positional in brackets, leaving it out in a terminal opens a picker; in a script it is required. An `<agent>` is an agent ID or the name of exactly one agent. `--template` and `--vault` likewise take an ID or the name of exactly one environment template or vault; a name two of them share is an error that lists their IDs.

## Sign-in and setup

```text
orca login | orca auth login [--api-url u] [--label l] [--no-browser] [--with-token orca_sk_...]
orca whoami | orca auth whoami
orca auth status
orca auth logout [--revoke] [--yes]
orca context list | use [name] | show
orca doctor [--strict]
orca update [--check] [--tag t] [--force]
```

See [install and sign in](/cli/install).

## Chat

```text
orca chat [agent] [prompt...] [--session id] [--sandbox] [--template t] [--vault v]... [--file path[:dest]]...
```

- **With no prompt** in a terminal, `orca chat` opens a conversation. Ctrl-C cancels a running turn on the server, then exits and prints the command that resumes the session.
- **With a prompt or piped input** it runs one turn and streams the answer to stdout. The session ID goes to stderr, so a script can continue with `--session`.
- Without `--session` it creates a session first, with no sandbox. `--sandbox` gives it a managed sandbox, `--template` builds the sandbox from an environment template, and `--vault` lets its tools use a vault's credentials. Both take an ID or a name.
- `--file` puts a file from your machine into the sandbox. See [files in and out of a sandbox](#files-in-and-out-of-a-sandbox).

```bash
orca chat support                                   # a conversation
orca chat support "summarize the open tickets"      # one turn
echo "and the oldest?" | orca chat support --session sess_123
```

When a turn ends because Orca credit or your provider account's quota ran out, `orca chat` in a terminal says which, shows the warning about switching, and asks whether to top up or switch who pays for this session. Outside a terminal it prints the reason and the session ID and exits 1. See [switch who pays](/providers#switch-who-pays-for-one-session).

## Agents and sessions

```text
orca agents list
orca agents get [agent]
orca agents create -f agent.yaml           # YAML or JSON; - reads stdin
orca agents update <agent> -f fields.yaml  # only the fields in the file change
orca agents delete [agent] [--yes]

orca models [--payer orca|<provider>]      # every model you can use, grouped by who pays

orca sessions list [--agent agent]
orca sessions get <id>                     # includes the session's cost, tokens, and machine time
orca sessions create --agent <agent> [--sandbox] [--template t] [--vault v]... [--file path[:dest]]...
orca sessions items <id> [--limit n]
orca sessions artifacts <id>               # the files its turns saved under /workspace/outputs
orca sessions artifacts download <id> [artifact] [-o path|-] [--all]
orca sessions delete <id> [--yes]
```

The file for `agents create` is the body of `POST /v1/agents`. The model says who pays:

```yaml
model: orca/openrouter/openai/gpt-5.6-luna   # or anthropic/claude-sonnet-4-5 on your Anthropic key
name: support
instructions: |
  You answer support questions.
reasoning: { effort: medium }
```

In a terminal, a file with no `model` opens a picker of every model you can use, grouped by who pays. The server checks every field and the CLI prints its message. See [models and provider keys](/providers).

`orca models` lists the same names anywhere, including in scripts and coding agents: one line per model with its name, who pays (`orca`, or the provider whose key you saved), and OpenRouter's price for Orca credit models. `--payer orca` or `--payer anthropic` keeps one group, and `--json` prints the server's list.

```bash
orca models --payer orca | grep luna
```

### Files in and out of a sandbox

`--file <path>[:<dest>]` on `orca chat` and `orca sessions create` uploads a file from your machine and puts it in the session's sandbox, at `/workspace/<its name>` unless you give a destination after the colon. A relative destination is under `/workspace`. Repeat it for more files. It implies `--sandbox`, and with `--session` it puts the files into that session's sandbox before the message is sent. A file over the [size limits](/guides/files-and-artifacts#size-limits) is refused before anything is uploaded. The uploaded files stay in `orca files list` until you delete them.

Files the agent saves under `/workspace/outputs` are kept as artifacts when its turn completes. `orca sessions artifacts <id>` lists them with their path, size, and turn. `orca sessions artifacts download <id> <artifact>` saves one, given its ID or its path as listed, under its own file name, or to `-o path`, or to stdout with `-o -`. `--all` saves every file from the newest turn into the current folder, or the folder `-o` names. A file name from the server never leaves that folder.

```bash
orca chat support --file sales.csv "Chart /workspace/sales.csv into /workspace/outputs/chart.png"
orca sessions artifacts download sess_123 --all -o results
```

Deleting the session stops its sandbox and deletes its artifacts.

## Skills, vaults, and files

```text
orca skills list | get <id> | delete <id> [--yes]
orca skills create <folder>                # a folder with SKILL.md

orca vaults list | create <name> | delete <id> [--yes]
orca vaults credentials list <vault>
orca vaults credentials add <vault> --name n --server https://... [--token t | --basic --login l]
orca vaults credentials delete <vault> <id> [--yes]

orca files list
orca files upload <path> [--name filename]
orca files download <id> [-o path|-]
orca files delete <id> [--yes]
```

Creating and deleting vaults and credentials needs the admin role. `credentials list` shows each credential's type. `credentials add` takes the vault's ID or name, and adds a bearer token by default, read from `--token`, stdin, or a hidden prompt.

With `--basic --login <login>` it adds a [login and password](/guides/credentials#a-login-and-password) instead, which Orca sends to the server as HTTP Basic. The password comes from stdin or a hidden prompt. There is no password flag, by design: a flag stays in your shell history. Passing `--password` is refused, and its value is never printed.

```bash
orca vaults credentials add dataforseo --name dataforseo --server https://mcp.dataforseo.com/mcp --basic --login YOUR_API_LOGIN
printenv DATAFORSEO_PASSWORD | orca vaults credentials add dataforseo --name dataforseo --server https://mcp.dataforseo.com/mcp --basic --login YOUR_API_LOGIN
```

The first asks for the password at a hidden prompt; the second reads it from an environment variable. There is no rotate command: delete the credential and add it again, or rotate it on the dashboard's Vaults page.

## Kits

```text
orca kits show <link|public-id> [--json]   # the review, no login needed
orca kits copy <link|public-id> [--name key=name]... [--skip key]... [--dry-run] [--yes]
```

Only Orca publishes kits, so these two are the only kit commands (1.4.0 or later). `show` prints the kit's review: what it runs, reaches, and spends, then each agent, skill, and template in full. `copy` prints the same review, asks, and copies the version it printed. `--yes` skips the question, for a coding agent after you have said yes. See [kits](/kits).

## API keys

```text
orca keys list
orca keys create [name]
orca keys revoke <id> [--yes]
```

`keys create` prints the key once. In a pipe, stdout carries only the key: `ORCA_API_KEY=$(orca keys create ci </dev/null)`.

## Billing and usage

```text
orca usage [--days n] [--group-by model|provider|credential|session|agent] [--session id] [--meter m]
orca usage events [--meter m] [--charged]   # --charged: only the rows that cost something

orca billing wallet                          # balance, plan, period, and packs on sale
orca billing buy pro|max|pack:<cents> [--no-open]
orca billing manage [--no-open]              # the billing portal
```

`orca usage` charts one meter (`--meter`, `model_tokens` by default) from the server's series: by the hour for `--days 1` or `2`, by the day up to 366 days, captioned **Hourly (UTC)** or **Daily (UTC)** as on the dashboard. A longer window has no chart. `orca usage --group-by` shows each key's tokens and its cost across every meter. In `orca usage events`, a row whose money is on another row says where: a token row reads `on its call` (its call's row carries it), a web search's tool call reads `on its search`, and every row of a call charged later reads `charged later`, its money on its `late_charges` row (see [calls charged later](/wallet#calls-charged-later)). `orca usage` lists `late_charges` like any meter. When the balance is below zero, `orca billing wallet` adds "Your balance is below zero. Paid work resumes when credit brings it to `<minimum>`." Web searches are counted in `searches`, the searches the provider ran, not tool calls; see [what is counted](/providers#what-is-counted).

`billing buy` and `billing manage` need the admin role. They print the Polar link and open it in a browser. See [wallet and credit](/wallet) and [plans](/plans).

## Output

- `--json` on any list or get command prints the raw API response.
- When stdout is not a terminal, output is plain tab-separated lines, so `orca agents list | cut -f1` works. A reader that stops early, such as `head`, ends the command quietly.
- List commands take `--limit N` (1 to 100, default 10), `--after <id>`, and `--all`.

| Exit code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | API or network error, or a chat turn failed |
| `2` | Usage or validation error |
| `3` | Missing or invalid key, or not allowed for your role |
| `4` | Not found, or gone |
| `130` | Interrupted with Ctrl-C |

## Commands that ended

CLI 1.0 removed the commands for features that ended with Orca 1.x: `run` and `runs`, `pools`, `workflows`, `memory`, `storage`, `stats`, `topology`, `bundles`, `apps`, `secrets` (now `vaults`), `credit`, `billing cap`, `agents publish` and `agents keys`, and the MCP server catalog (`mcp list`, `mcp add`, and the rest). `kit add` is now `kits copy`. Running one of them gives `unknown command`. See [bring your agents to the new Orca](/migration).

CLI 1.4.0 removed `kits list`, `kits make`, `kits edit`, `kits publish`, and `kits withdraw`, since only Orca publishes kits. In an older CLI they print "Kits are published by Orca. You can copy Orca's kits from their pages." and exit 3.
