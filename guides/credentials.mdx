---
title: Credentials and vaults
description: Bind remote service credentials to sessions without exposing them to agents.
---

Your Orca API key authenticates your application to the server; model-provider keys and MCP credentials are separate. Never include secrets in prompts, function results, skills, uploaded files, or logs. For MCP, create a tenant vault and a credential bound to the **exact HTTPS MCP server URL**, then attach the vault with `vault_ids` at session creation. The remote origin must also be allowed by your deployment. This is Orca-specific behavior with official OpenAI Python `3.13.0` and TypeScript `7.15.0` clients; see the [upstream Agents API quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart/) for general concepts and [the quickstart](/quickstart) for client configuration.

```python
import os
from openai import OpenAI
client = OpenAI(api_key=os.environ["ORCA_API_KEY"], base_url=os.environ["ORCA_BASE_URL"])
vaults = client.beta.agents.vaults
url = "https://mcp.example.com/orders/mcp"
vault = vaults.create(name="orders")
try:
    cred = vaults.credentials.create(vault.id, name="read-orders", auth={
        "type": "static_bearer", "mcp_server_url": url,
        "token": os.environ["ORDERS_MCP_TOKEN"],
    })
    try:
        # Attach vault_ids=[vault.id] when calling client.beta.agents.sessions.create(...).
        # Rotate the credential without fetching the old plaintext:
        vaults.credentials.update(cred.id, vault_id=vault.id,
                                  auth={"type": "static_bearer",
                                        "token": os.environ["NEW_ORDERS_MCP_TOKEN"]})
    finally:
        vaults.credentials.delete(cred.id, vault_id=vault.id)
finally:
    vaults.delete(vault.id)
    client.close()
```

Credential responses do not return plaintext; store original tokens safely and rotate by replacement. Only attach vaults a session needs, and limit agent tools with `allowed_tools` (see [MCP](/guides/mcp)). A missing required credential can cause MCP session creation to fail. Restrict who can access your Orca key: it authorizes resources for its tenant. For bring-your-own model keys, Orca also exposes `/api/providers` on the server origin (outside `/v1`): `PUT /api/providers/{id}/key` with `{"api_key":"..."}`, `GET /api/providers/{id}/models`, and `DELETE /api/providers/{id}/key`. A prefixed `agent.model` such as `openai/gpt-5` uses the tenant's provider key, not an implicit fallback to the deployment model key; removing that key can fail the next model call of an existing session. Select a model from the provider catalog and keep provider keys out of vaults intended for MCP. See [reliability](/guides/reliability), [runnable examples](/examples), and [vault reference](/reference/resources#vaults-and-credentials).
