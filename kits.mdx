A kit is a set of agents, skills and templates that Orca publishes. Anyone can read Orca's kits, and any organization can copy one. A copy becomes ordinary resources in the copier's organization, with no link back to the kit.

<Note>
Orca's kits are in the [Kits tab](/kits/scout), each with a page that takes you from copying it to running it from your own code.
</Note>

## What a kit carries

- **Agents**, with their model, instructions, and tools.
- **Skills**, with every file in them.
- **Environment templates**, with their inline files, packages, setup commands, and network policy.

**Secrets never travel.** Vault credentials and the values of template environment variables are left out. The kit lists them as credentials the copier adds after copying.

A kit has a name and a description, and its page says it is by Orca. It holds at most 50 of each kind of resource. When Orca changes a kit, it publishes a new version under the same link. The link looks like `https://app.orcapods.ai/kits/kit-` followed by 17 letters and digits.

## Copy a kit

Open the kit's link.

- **Signed out:** choose **Get started** to make your Orca account and your own copy.
- **Signed in:** choose **Get started**, then choose what to copy and what to call each copy, and choose **Copy**.

From the CLI, 1.4.0 or later:

```bash
orca kits show https://app.orcapods.ai/kits/kit-xxxxxxxxxxxxxxxxx    # what it holds, no login needed
orca kits copy https://app.orcapods.ai/kits/kit-xxxxxxxxxxxxxxxxx    # prints the same, asks, then copies
```

`orca kits show` prints the kit's review: that Orca publishes it, the version, and three lines on what it runs, what it reaches, and what it spends. Then it prints each asset in full:

- **Agents:** model, reasoning effort, service tier, instructions, and every tool, with each MCP server's URL and allowed tools.
- **Skills:** every file with its size, `SKILL.md` and the other text files in full up to 64 KiB each. A longer or binary file is shown by its size and SHA-256.
- **Templates:** network, packages, every setup command in order, and inline files.
- **Credentials** to add after copying, and where each is used.

`--json` prints the review as the API returns it.

`orca kits copy` prints the same review and asks before it copies anything. It copies the version it printed. `--dry-run` prints the review and stops. `--name agent-1=my-support` copies an asset under another name, and `--skip skill-1` leaves one out.

`--yes` skips the question. It is for a coding agent, after you have said yes: the agent runs `orca kits show <link>`, shows you what it prints, and copies with `orca kits copy <link> --yes` only once you agree. Without `--yes` and without a terminal, `copy` exits 2.

If the kit changes while you read, nothing is copied: the CLI prints "This kit changed while you were reading" and the new review. Read it and copy again.

With the API, read the review with `GET /api/public/kits/{public_id}/review` (no key needed). Its `version` is the version it describes. Then `POST /api/kits/{public_id}/copy` with that version, and each asset to copy with its new name:

```json
{"version": 3, "assets": [{"key": "agent-1", "name": "my-support"}]}
```

A copy is all or nothing. It is refused, and nothing is copied, when:

- **The kit changed.** Orca published a newer version after the review you read: HTTP 409 `kit_changed`, "This kit has a newer version (4). Review it again before copying.", with the newest version in `error.current_version`. Read the new review and copy with its version.
- **The version is missing.** A copy without `version` is HTTP 400 on `version`: "Update the Orca CLI (orca update) to copy kits." A CLI older than 1.4.0 gets this answer.
- **A name is taken.** A copy would take a name already used by the same kind of resource: HTTP 409 `name_taken`. Choose other names and copy again.
- **A model needs a key you do not have.** Each agent's model is checked as on any [save](/providers#select-the-model-explicitly), so an agent that runs on a provider's own key needs your key for the same provider. Without it the response is HTTP 400 on `assets`, such as "own cannot be copied: Add your OpenAI key in Settings, Providers, or choose an Orca credit model". Add the key and copy again.

After a copy, add the credentials the kit lists: an MCP server's credential goes in a vault, and an environment variable goes on the copied template.

A kit Orca withdrew returns HTTP 410 `kit_withdrawn`. A link to any other kit returns 404, as an unknown link does. Copies already made are not affected.

## Routes

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/public/kits` | Orca's kits, newest first, no key needed |
| GET | `/api/public/kits/{public_id}` | A kit's public page, no key needed |
| GET | `/api/public/kits/{public_id}/review` | The review of its newest version, with `version`, no key needed |
| POST | `/api/kits/{public_id}/copy` | Copy it into your organization: `{"version", "assets"}`. 409 `kit_changed` when a newer version exists |

Paths are relative to `https://api.orcapods.ai`, without `/v1`. The routes that make, edit, publish, and withdraw kits answer HTTP 403 `kits_are_published_by_orca` to every organization.
